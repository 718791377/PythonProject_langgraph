# Comet Management Checklist

## Open / Value Definition

- [x] Value/why is stated.
- [x] Success criteria are stated.
- [x] Stakeholders or constraints are identified.

## Design / Delivery Framing

- [x] Delivery approach is tailored to the change size.
- [x] Risks and key assumptions are recorded.
- [x] Acceptance evidence path is identified.

## Build / Execution

- [x] Execution mode is selected.
- [x] TDD / review / quality evidence is recorded.
- [x] Blockers are cleared or explicitly decided.

## Verify / Acceptance

- [x] Variance from proposal/design/tasks is checked.
- [x] Risk and change impact are assessed.
- [x] Control decision is recorded.

## Archive / Closing

- [x] Value outcome is summarized: startup canary markers are now transport-stable while legacy/corrupted evidence remains fail-closed.
- [x] Lessons learned or reusable guidance are recorded: keep visible sentinel text ASCII-stable and assemble checker/test constants from fragments or codepoints.
- [x] Delta spec sync, verification evidence, and archive path are confirmed: targeted checkers/tests and OpenSpec guard passed before archiving to `openspec/changes/archive/2026-05-29-fix-canary-ascii-marker-mojibake-20260529`.

## Monitoring Loop

- [x] Current facts are checked.
- [x] Continue, adjust, stop, or return decision is made.
