## Design

### 根因

旧的可见 canary 标记包含非 ASCII 字符。在 UTF-8 文件中它是正确的，但经过旧 Windows 控制台、启动器 payload 或错误解码链路时可能显示为乱码。若继续把该标记作为当前可见证据，用户会看到不稳定文本。

### 设计决策

1. 当前可见 canary 标记改为 ASCII-only 起止 token。
2. 启动摘要双文件仍是唯一字面标记来源。
3. 检查器和测试中不得出现完整当前字面标记；必须通过片段组装。
4. 历史非 ASCII 标记及其旧编码损坏变体继续作为无效证据检测。
5. 响应/session 诊断仍只统计用户可见 assistant 响应，不把工具输出、文件读取或上下文副本算作 canary 证据。

### 风险与缓解

- **风险：** 当前标记若被复制到其他源文件，会削弱唯一来源规则。  
  **缓解：** canary surface 检查器继续扫描并失败关闭。
- **风险：** 历史标记被误认为仍然有效。  
  **缓解：** 历史标记和损坏变体均报告为 `mojibake_canary`。
- **风险：** 中文伴随文档再次出现乱码。  
  **缓解：** 使用 UTF-8 写入并运行 OpenSpec guard。
