# Comet Management Record

## Open / Initiating
- [x] Value and why are stated.
- [x] Success criteria are measurable.
- [x] Stakeholders, constraints, or operating boundaries are identified.

## Design / Planning
- [x] Delivery approach is tailored: repo-local deterministic guard before user-level install activation.
- [x] Major risks and assumptions are recorded.
- [x] Acceptance evidence path is defined.

## Build / Executing
- [x] Execution mode is selected: isolated worktree plus direct implementation.
- [x] Quality evidence is recorded through unit tests, baseline checker, OpenSpec guard, local gate, and local MR review.
- [x] Blockers are cleared or serialized.

## Verify / Controlling
- [x] Variance from scope, design, and acceptance criteria is checked.
- [x] Risk and change impact are assessed.
- [x] Control decision is recorded as `continue`, meaning the slice passed scope and risk checks and should proceed to local commit plus local-main integration without returning to design.

## Archive / Closing
- [x] Value outcome is summarized.
- [x] Lessons learned are recorded.
- [x] Delta spec sync, verification evidence, and archive path are confirmed.

## Monitoring Loop
- [x] Current facts are checked.
- [x] Continue decision is made.
- [x] No return to earlier phase is required.
