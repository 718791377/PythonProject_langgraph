## Why

The global automatic collaboration rule has been written into user-level docs and repository governance, but managed user-level assets can be regenerated by the installer and overwrite manual edits. This change hardens the rule in the repository source templates, tests, and checkers so all projects and all sessions inherit the default without requiring repeated prompt reminders.

## What Changes

- Add an explicit global automatic collaboration default to managed team-mode playbook and quick-reference generator output.
- Add the same default to generated model instructions and the team-leader profile so wrapped sessions receive the rule at startup.
- Extend checker-backed governance so missing-reminder wording cannot regress and `platform_subagent_invocation_constraint` is preserved as the correct blocker token.
- Add regression assertions that generated user-level docs and launcher instruction payloads contain the global default rule.

## Capabilities

### New Capabilities

- None.

### Modified Capabilities

- `codex-user-level-orchestration-activation-policy`: make the global automatic collaboration default a spec-level requirement and require platform/tool subagent blockers to be reported as concrete blockers rather than user missing-reminder reasons.
- `codex-user-level-team-mode-quick-reference-card`: require the generated quick-reference card to include the global automatic collaboration default so managed regeneration cannot silently drop it.

## Impact

- `tools/install-codex-user-level-team-mode.ps1`: managed user-level docs, team-leader profile, and startup model-instructions templates.
- `tools/check_orchestration_activation_policy.py`: checker snippets for the global default and platform-blocker token.
- `test/install-codex-user-level-team-mode.test.ps1`: installer regression coverage for generated docs and launcher instruction payloads.
- `docs_bilingual/governance/codex_user_level_orchestration_activation_policy.*`: bilingual source-of-truth governance wording.
- `openspec/specs/*`: stable behavior contracts for activation policy and quick-reference surfaces.

## Explicit Non-Goals

- Do not bypass the current platform contract for native `spawn_agent` invocation.
- Do not force every small single-slice task into a durable or persistent team.
- Do not mutate `C:\Users\lenovo\.codex\config.toml`.
- Do not install or upgrade LangGraph or Codex.

## Rollout Sequence

1. Update repository source templates and policy docs.
2. Add checker/test assertions that generated assets retain the global default rule.
3. Run targeted validation, then OpenSpec guard and local gate as appropriate.
4. Archive the change after validation and integrate as one local package.

## Rollback Plan

Revert the local commit or restore the affected generated user-level files from the `.bak.<timestamp>` backups created before manual user-level edits. Because this change is source-template based, rollback must also revert the installer/checker edits to prevent regeneration from reintroducing the rule.

## Validation Path

- `check_orchestration_activation_policy.py` - verifies the policy surfaces keep the global automatic collaboration default and platform blocker token.
- `install-codex-user-level-team-mode.test.ps1` - verifies managed installer output for docs, team-leader profile, and launcher instruction payloads.
- `run_openspec_guard.py --tool codex` - verifies OpenSpec, governance, implementation-plan, and naming guard rules.
- `local_gate.ps1` - runs the shared local CI gate before integration when time and scope permit.
