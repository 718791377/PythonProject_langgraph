# D:\PythonProject_General Phase 0 General Governance Template Plan

## 1. Goal

`D:\PythonProject_General` is the fuller reusable Codex/OpenSpec/Comet production template. Phase 0 does not clone `D:\PythonProject_langgraph`; it turns reusable governance capabilities into template-safe, verifiable, and reversible foundations.

After Phase 0, generated projects should inherit cold-start summaries, OpenSpec governance, Superpowers practices, Comet workflow explanations, local/remote gate parity, MCP scope boundaries, Windows-safe launcher payload rules, and optional LangGraph/OMX template entry points. Live runtime state must be generated by the new project after hydration, not copied from this repository.

## 2. Capability Positioning

### 2.1 General vs General_2

- General is the fuller governance template. It may template oh-my-codex, native_omx, LangGraph compatibility source, MCP scope policy, launcher payload policy, local/remote CI/MR gate parity, and generated-project repo-local durable-state scaffolding.
- General_2 is the local-only template. It only allows local Git, OpenSpec, Superpowers governance, and native Codex subagents. It does not enable remote CI/MR, oh-my-codex, native_omx, LangGraph durable backend, or `.omx/state/`.

### 2.2 Comet Boundary

`/comet` means the OpenSpec + Superpowers dual-star governance workflow. OpenSpec owns WHAT, proposal, spec, tasks, validate, and archive. Superpowers owns HOW, brainstorming, writing-plans, executing-plans, and verification-before-completion. Comet coordinates phase routing, state evidence, and archive closure.

Comet is not native subagent evidence, oh-my-codex, native_omx, LangGraph, or a durable-team backend. Any plan reference to Comet must say so.

## 3. Phase 0 Scope

### 3.1 In Scope

- Update `AGENTS.md` with cold-start read order, OpenSpec/Comet/Superpowers boundaries, multi-session/worktree isolation, MCP scope, launcher payload, orchestration activation, and prompt-sentinel rules.
- Update `README.md` and startup summaries so a new Codex session can find template goals, generation flow, validation commands, and rollback paths.
- Update `docs_bilingual/docs_registry.yaml` for long-lived bilingual governance documents and implementation plans.
- Provide `tools/test_template_hydration.py` to generate a temporary project and verify that hydrated output has no unresolved placeholders.
- Provide `tools/ci/local_gate.ps1` and `tools/ci/local_mr_review.ps1`; remote CI/MR must call the same scripts instead of maintaining a divergent sequence.
- Provide a manifest-driven gate with JSON reports for Python, Node, and PowerShell checks.
- Template `tools/langgraph_durable_orchestrator/` as optional compatibility source while keeping the official `langgraph` package in user-level shared installation.
- Describe `.omx/state/langgraph/` as generated-project local state only, never as copied live state.

### 3.2 Out of Scope

- Do not copy this repository's `.omx/state/`, active selectors, worktree claims, LangGraph backend JSON, logs, or current mainline facts.
- Do not edit user-level `C:\Users\lenovo\.codex\config.toml`, global pip/npm/Git configuration, or browser configuration.
- Do not write legacy consumer-project facts as general template defaults.
- Do not implement business application code, GUI, browser automation, Vercel/GitHub publication, or persistent team runtime in Phase 0.
- Do not push to remotes or create GitLab/GitHub MR/PRs.

## 4. Implementation Sequence

1. Read source truth: start from `docs_bilingual/project_startup_summary.md` and `.zh-CN.md`, then read OpenSpec, MCP scope, launcher payload, LangGraph runtime, multi-session worktree isolation, and orchestration activation policies.
2. Inspect the target: run `git status --short`, `openspec list --json`, and template checkers in `D:\PythonProject_General`; stop when uncommitted human changes exist.
3. Update governance documents with reusable template rules, not live state or session facts.
4. Update scripts and gates so local gate, local MR review, and remote CI/MR use one manifest and one checker sequence.
5. Update runtime scaffolding: keep LangGraph compatibility source optional and describe `.omx/state/` as generated local state.
6. Run hydration smoke tests for placeholders, startup summaries, OpenSpec, background process entrypoints, launcher payloads, and local gates.
7. Commit locally after pre-commit update/archive checks, OpenSpec guard, local gate, and local MR review pass; do not publish remotely.

## 6. Acceptance Criteria

- General is clearly the fuller governance template and does not mix in General_2 or live runtime state as defaults.
- Comet is defined as OpenSpec + Superpowers governance, not native subagent, OMX, LangGraph, or durable team.
- MCP scope, launcher payload, LangGraph runtime source, repo-local `.omx/state/`, and local/remote gate parity have template-safe validation paths.
- Generated projects ignore or locally generate `.omx/state/`, `.venv/`, `node_modules/`, `.env`, tokens, coverage, and temporary reports.
- Chinese documents are UTF-8 clean and contain no mojibake.

## 7. Rollback

- Revert the local Git commit for document mistakes and rerun `git diff --check` plus OpenSpec guard.
- In `D:\PythonProject_General`, use local Git to revert target-template mistakes; if uncommitted, restore by the `git status --short` file list.
- Keep failed hydration temporary directories and JSON reports for diagnosis, then rerun smoke tests after fixes.
- Revert only `tools/langgraph_durable_orchestrator/` template source or docs for LangGraph template mistakes; do not delete user-level official `langgraph` installs.
- Revert template launcher/helper generation logic for payload mistakes; do not mutate user-level launchers or global Codex configuration.
